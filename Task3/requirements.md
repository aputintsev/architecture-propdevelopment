## Требования к безопасности  
1. Необходимо выполнить требования законодательства в области персональных данных и биометрии, в частности, законов 152-ФЗ и 572-ФЗ.
2. Любое взаимодействие как с внешними системами, так и между нашими подсистемами должно выполняться с применением шифрования трафика по протоколу TLS версии не ниже 1.3.
3. Также шифрование должно применяться для хранилищ данных, включая их резервные копии.
4. Необходимо реализовать логгирование попыток входа, а также любых операций с конфиденциальными данными для возможности последующего анализа. При этом логи не должны содержать сами конфиденциальные данные.
5. Необходимо внедрить систему мониторинга и автоматического реагирования на угрозы безопасности.
6. Ключи шифрования, используемые в системе, должны надежно храниться с использованием аппаратных или программных методов хранения, а также регулярно обновляться и контролироваться в соответствии с политикой безопасности компании.
  
## Протоколы аутентификации и авторизации
1. Для аутентификации и авторизации клиентов будем использовать имеющийся сервис аутентификации. 
2. В качестве основного механизма аутентификации и авторизации рекомендуется использовать OAuth 2.0 с использованием протокола OpenID Connect для обеспечения единого входа и авторизации в системе. 
3. При реализации аутентификации и авторизации необходимо соблюдать принципы безопасности, такие как минимизация прав доступа, использование сильных паролей и двухфакторной аутентификации, а также регулярное обновление и проверка учетных данных пользователей.
4. Для авторизации во внутренних сервисах будем использовать механизм ролей.
5. Для авторизации во внешних системах будем использовать токены и сертификаты. Токены и сертификаты должны регулярно обновляться и храниться в защищенном хранилище.
  
## Взаимодействие между системами предприятия и внешней платформой
1. Доступ внешних систем к системам компании должен осуществляться через API Gateway с использованием белого списка разрешенных IP-адресов.
2. Конфиденциальные данные не должны передаваться внешним системам. В случае необходимости они должны быть токенизированы перед передачей.
3. Взаимодействие систем компании с внешними поставщиками должно осуществляться по HTTPS.
